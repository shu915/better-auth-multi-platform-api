## 状況: 完了
Web、モバイル(Expo)、デスクトップ(Tauri)から、Go を変えずに使われている。本番(Render)で動いている。実行中のタスクはない。

## できること(すべて main)
- JWT の検証(EdDSA のみ、JWKS をキャッシュ、iss・aud・exp・sub を検証。公開鍵を取れないときは 503)
- ルート: GET /health、GET /me、GET と PUT /me/profile(bio 1000 文字、NUL と不正な UTF-8 は 422、本体 16KB まで)、DELETE /me。CORS、no-store。user_id はトークンの sub だけから取る
- DELETE /me: 冪等(204)。JWT の auth_time が 5 分以内であることを要求する(403)。同じトランザクションで deleted_users に記録し、退会から 10 分は PUT /me/profile を 410 で断つ(退会の途中の書き込みで復活しないため)。他のテーブルの扱いは internal/userdata に宣言し、食い違いはテストで落ちる
- 耐障害: Recover、リクエストの期限(10 秒)、DB プール(10 接続)と statement_timeout(5 秒)、本番の設定の検査(https の JWKS、sslmode=require 以上)
- テスト: 単体、結合(実 JWT 検証 + 実ストア + 実 Postgres)。CI は Postgres を立て、SKIP があれば失敗にする。hooks と evaluator
- 本番デプロイ: Render(Docker、DB も Render、シンガポール)。マイグレーション 00001(profiles)と 00002(deleted_users)は適用済み。3 つのクライアントから本番で確認済み

## 運用メモ
- **Render の DB は 2026-11-08 に期限が切れる**(そのままにする方針)
- デプロイの順: 初回は Go が先、Web が後。Go が新しいことを要求し始める変更(例: auth_time)は、Web が先
- 新しいマイグレーションは、Go を出す前に、手元から本番の DB に適用する(docs/deploy.md)。先に Go を出すと 500

## 既知の限界(許容している)
- レート制限がない(前段で行うなら Cloudflare など)
- 退会が途中で止まったユーザー(Go のデータだけ消えて、Web のユーザーは残った)は、10 分は書けず(410)、たつと書ける
- DB の TLS は sslmode=require でサーバー証明書を検証しない。verify-full が通るかは未確認のため、コードでは強制しない
- /health は DB を見ない(スキーマ未適用でも緑)。/ready は未実装
- アプリ用の DB ユーザーが DDL の権限を持つ
- JWKS の再取得に 15 秒のクールダウンがあり、鍵のローテーション直後に偽の kid で消費されると、新しい kid の正規トークンが最長 15 秒 401 になる
- JWT の最大有効期間は exp の存在しか見ていない(5 分は Web 側の設定頼み)
- 複数端末からの更新は後勝ち(必要になったら If-Match などの楽観ロック)
- Dockerfile のベースイメージはタグ固定のみ(digest 固定ではない)
- Render の無料プランはスリープする。スリープ明けの初回は Web が 5 秒で切れて bio が出ないことがある
