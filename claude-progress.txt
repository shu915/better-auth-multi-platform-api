  - bio は最大 1000 文字、NUL と不正な UTF-8 は 422、本体は 16KB まで(超えると 413)
  - エラーの JSON 形式は middleware.WriteError に一本化
- Web の画面から PUT /me/profile までの手動確認(人間が実施済み)
- テスト(DB を使うテストは TEST_DATABASE_URL がないと SKIP)
- evaluator エージェント(.claude/agents/evaluator.md)と、実装後のループ運用(CLAUDE.md)
- 退会時のデータ削除(feat/account-deletion。PR 作成済み): `DELETE /me`(204、冪等、sub だけを使う)。消すのは profiles の1行で、他のテーブルは user_id の外部キーで扱いが決まる
  - 全部カスケードにはしない。user_id を持つテーブルは、internal/userdata の Tables に delete / anonymize / retain を理由つきで宣言する。外部キーが宣言と食い違う、または宣言がないと、TestDeclaredPoliciesMatchTheSchema が落ちる
  - 検証: gofmt・vet・build・test が通過。TEST_DATABASE_URL を設定して SKIP 0 件。壊すと落ちることを確認済み(WHERE なしの DELETE、ルートの削除、クエリの user_id を使う、宣言のないテーブル)
  - 既知の限界: 退会後も JWT は最大 5 分有効で、その間の PUT /me/profile が行を作り直す。許容している

- 結合テスト(chore/tests-and-leftovers): cmd/server/integration_test.go(5 件)と internal/testdb。実 JWT 検証 + 実ストア + 実 Postgres を通す。実装を壊すと落ちることを確認済み(DELETE が消さない、GET が ?user_id を信用する、未知のフィールドを許す)。Stop hook は、開発 DB が起動していれば TEST_DATABASE_URL を自動で渡す。CI への Postgres 追加は、.github/workflows が hook で保護されているため、人の作業(差分は報告済み)

## 未対応のレビュー指摘(デプロイ前に決める)
- DB クエリに期限がない: http.TimeoutHandler、プールの MaxConns と statement_timeout を入れる
- Neon の pooled URL(PgBouncer)を使う場合、pgx のプリペアドステートメントでエラーになる可能性がある。QueryExecMode を確認する
- 本番で AUTH_JWKS_URL の http://localhost を許してしまう。本番は https のみにする
- panic を拾う Recover ミドルウェアがない
- レート制限がない(ALB と WAF で行う案)
- DB の TLS は sslmode=require だとサーバー証明書を検証しない。verify-full を検討する
- 複数端末からの更新は後勝ち(必要になったら If-Match などの楽観ロック)
- トークンの失効と削除済みユーザー(JWT は最大 5 分有効。退会の直後に PUT /me/profile が来ると行が作り直される。今は許容。DELETE /me の追加で、削除との同期の入口はできた。Web 側の退会は実装済みで、他セッションの失効 → DELETE /me → ユーザー削除の順に呼ぶ)
