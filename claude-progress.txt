## 未対応のレビュー指摘(デプロイ前に決める)
- (Go の DB は Render なので、Neon の pooled URL の件は当てはまらない)
- レート制限がない(許容。前段で行うなら Cloudflare など)
- DB の TLS は sslmode=require だとサーバー証明書を検証しない(Render の証明書で verify-full が通るか未確認のため、コードでは強制しない。通るなら URL を verify-full にする)
- /health は DB を見ない(スキーマ未適用でも緑)。/ready(SELECT 1)は未実装
- アプリ用 DB ユーザーが DDL 権限を持つ(SELECT/INSERT/UPDATE/DELETE だけのユーザーに分けるのが望ましい)
- 複数端末からの更新は後勝ち(必要になったら If-Match などの楽観ロック)
- トークンの失効と削除済みユーザー(JWT は最大 5 分有効。退会の直後に PUT /me/profile が来ると行が作り直される。今は許容。DELETE /me の追加で、削除との同期の入口はできた。Web 側の退会は実装済みで、他セッションの失効 → DELETE /me → ユーザー削除の順に呼ぶ)
